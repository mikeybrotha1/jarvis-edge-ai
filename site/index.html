Jarvis Edge AI

Edge-AI platform for Raspberry Pi 5 with Hailo-10H acceleration.

A separate vision process detects objects on device. PostgreSQL is the durable memory. A FastAPI process that never loads the camera serves a timeline, live activity, zones, alerts, webhooks, and a zero-build console.

What works today

README status is v1.0.0. The capabilities below are the ones that repository documents as working. Nothing on this page is a benchmark, a customer count, or a feature that only appears on the roadmap.

Vision

Hailo, in its own process

On-device object detection with a Hailo-10H YOLOv6n detector and an Azure Kinect colour camera opened through V4L2. Vision is optional and separate from the API process.

Memory

Entity memory on PostgreSQL

Durable entities, observations, and snapshots, with Alembic migrations. PostgreSQL is the authoritative store.

History

Timeline API with cursors

Paginated historical activity and recovery-friendly cursors, so a client can resume without inventing events.

Live

Activity stream

Optional PostgreSQL LISTEN/NOTIFY plus a WebSocket feed. The stream is ephemeral. Tables remain the source of truth. Channel default: jarvis_activity.

Space

Zones, dwell, occupancy

Camera zones in normalised coordinates, dwell sessions, and occupancy. The API does not use Shapely or OpenCV for geometry.

Alerts

Durable alerts

Rules, evaluator state, consumer checkpoints, and a due reconciler. Alert state survives restarts because it is stored, not held only in memory.

Notify

Webhook outbox

Transactional outbox, SSRF-checked delivery, attempt history, and retries. HTTP runs after commit, outside the alert transaction.

Ops

Observability, retention, console

/health, /ready, and /api/v1/ops/status with bounded metrics. Retention is config-driven and safe by default. The Live Activity Console is zero-build HTML, CSS, and vanilla JS.

Process boundary

Camera, then Hailo, then the database, then the API

The API process never loads camera, Hailo, OpenCV, or NumPy. Vision remains a separate edge process when it is used.

Camera

Azure Kinect colour frames through V4L2. Opened only by the vision process.

Hailo vision process

YOLOv6n on Hailo-10H. Writes durable rows and pg_notify in the same transaction.

PostgreSQL

Authoritative store for entities, zone sessions, alerts, checkpoints, and the notification outbox. Alembic owns the schema.

API process

FastAPI. Timeline, entities, zones, alerts, webhooks, ops. One async LISTEN connection when the stream is enabled.

The API never imports the sensor stack

Documented constraint, checked in architecture notes and API startup: no camera, no Hailo, no OpenCV, no NumPy. A console and a webhook worker can run with only the API and PostgreSQL.

Live Activity Console

Same-origin static UI. Timeline, entities, zones, alerts, notifications, and an Operations panel. No Node build, no live video.

Durable alerts

Rules and evaluator state, a consumer with checkpoints, and a due reconciler. Readiness uses recent errors, not a permanent historical stain.

Webhooks

Outbox rows commit with the alert. A worker delivers HTTP afterward, with SSRF checks and recorded attempts.

How it is built

Production habits, visible in the tree

Typed YAML configuration, explicit safety defaults, a transactional outbox, and a pytest suite that covers the API without hardware.

Safe by default

Upgrading does not start deleting data. Retention ships off, and a destructive manual run stays blocked until several guards are set. Ops payloads omit DSNs, credentials, Fernet keys, paths, raw SQL, and exception stacks. There is no built-in authentication: ops and retention assume a trusted local or edge network. 

ops.retention.enabled: false
ops.retention.dry_run: true
ops.retention.allow_manual_destructive_run: false
# every retention domain enabled: false

Transactional outbox

When an alert matches webhook targets, the alert state and the notification_deliveries rows commit in the same database transaction. Outbound HTTP is not part of that transaction. After commit, a worker claims rows (FOR UPDATE SKIP LOCKED on PostgreSQL), delivers, and records each attempt.

Delivery is at-least-once. Receivers dedupe on X-Jarvis-Delivery-ID. Statuses are pending, processing, delivered, failed, and exhausted. Targets must be http or https, with no embedded credentials. Loopback, link-local (including cloud metadata), and private addresses are blocked by default.
